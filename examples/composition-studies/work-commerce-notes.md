# Operational and commerce implementation notes

Both pairs consume the frozen shared fixture and original assets through the shared study shell. They are authored examples, not independent skill-efficacy evidence. Module sources were formatted and passed `node --check`; final browser evidence is recorded by the shared harness rather than inferred from this source inspection.

## Operational

Problem → the operator compares stock, then records one bounded decision. The conventional worksheet keeps the complete comparison above the decision; the adapted condition places comparison and selected evidence beside each other wide, then replaces the overview with focused detail narrow. This reduces the intervening stock list while deciding; it loses simultaneous narrow comparison. The continuous worksheet remains useful for multi-row scanning. No win is claimed from the layout alone.

Ledger rules and tabular quantities support comparison. Restrained green marks selection/action, and warm neutral stock sheets retain the maintained system-font and Vietnamese-content constraints. Both variants keep the same rows, evidence, quantity range, review/edit, first-save failure, retry and local success. Search/filter controls are not rerendered while typing. Per-item drafts survive return and selection; no reload persistence is promised.

Hooks: `op-search`, `op-shortage`, item buttons with `data-sku`, `op-quantity`, `op-review`, `op-edit`, `op-save`, `op-retry`, `op-back`. No-results reset is `op-reset`. Invalid quantity focuses its field; transitions focus the selected heading or error/success message; return restores the list's scroll and opening item focus when still in the result set.

Sources actually read for implementation: frozen `briefs.md` and `fixtures.json`, `shared.css`, and maintained `examples/inventory-workbench/UX_PLAN.md` plus `app.mjs`. The latter supplied task/focus/retention lessons; the maintained source and historical evidence were not edited. No new external source or asset was copied.

## Commerce

Problem → a single schematic must support object fit and a complete variant/quantity/cost decision. The conventional product composition presents media beside details/options, then complete care/delivery/returns below. The adapted object sheet groups the image with specifications, and places conditions beside the order form within the decision column. Narrow reading follows object evidence → choices/total → conditions. The adaptation makes the relationship of conditions to commitment explicit; the familiar product layout remains suitable with richer photography and has less dense decision-column content.

Earth colors and serif object naming suit the supplied clay schematic; ruled specifications and tabular costs keep the artifact factual. Both conditions use the same asset/caption and every declared fit/care/shipping/returns fact. The drawing is explicitly schematic, not glaze proof. No handmade, delivery or quality claim is introduced.

Hooks: `co-glaze` is an ordinary select with Sand/Iron/Ash values; unavailable Ash remains inspectable and disables Add. `co-quantity`, `co-add`, `co-retry`, `co-feedback`, `co-stock`, `co-subtotal`, `co-total` expose the bounded task. Iron quantity 3 remains editable and is rejected on submit with a retained-glaze error. Sand × 2 displays USD 84 + USD 6 = USD 90. First valid add fails; retry identifies the exact choices and total in the local success message. Changing either input clears stale success/failure without losing input focus.
