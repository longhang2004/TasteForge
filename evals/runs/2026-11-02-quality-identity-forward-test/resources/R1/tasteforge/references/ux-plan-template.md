# Compact decision record

Reuse existing project guidance. Fast usually needs only a finding and recheck in the final report. Standard can use four short lines; create a separate `UX_PLAN.md` only when a durable handoff is useful.

```markdown
Task: <route/user action and successful outcome>
Keep: <product facts/source, existing system, fixed choices, constraints>
Choice: <information order, decision placement and relevant state path; why>
Check: <minimum/representative widths, commitment/edit/error states, done condition>
```

Persist decisions that save rereading: selected structure/tokens, relevant source IDs/revisions, actual checks and open issues. Do not copy a conversation transcript or create empty evidence tables.

For Explore, add only what helps choose:

- Shared content/behavior and two runnable task-slice paths.
- Meaningful structural difference, audience benefit and tradeoff.
- Same decision/recovery states inspected at wide/narrow widths.
- Selected relationship and rejection reason; polish only the winner.

For actual research, retain source URL/path/revision, inspected material, observation versus inference, adaptation/rejection, and applicable reuse terms. If no browsing occurred, identify local evidence honestly.

For implementation review, use **target/state/width → observed issue → change → rechecked result → uncertainty**. Label natural viewport, optional top/full-page captures and actual scroll/focus. Separate source facts, runtime tests, AI judgment and human observations; absence of findings is not conformance or user validation.

This record is planning guidance, not an extra CLI/DNA schema. Preserve established context and meaningful exceptions; keep provenance out of customer flows unless it informs a real user decision.
