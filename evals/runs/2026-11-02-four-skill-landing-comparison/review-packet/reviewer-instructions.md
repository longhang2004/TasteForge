# Independent four-way UI review

Read only this instruction and review-packet/. Do not read run/gallery/results/key/resource/creator/preflight files or another reviewer. You authored none of these outputs. Labels A/B/C/D are randomized separately for each brief; no label/repository is preferred. Two reviewers receive the identical packet. At your first tool record UTC before reading; exact unsampled intervals/usage stay null.

This is a controlled single-creator, code-first, supplied-media/font, offline skill-layer study, not full native orchestration or a model ranking. Read both common task facts. Inspect actual normal wide/narrow renders and consequential decision/failure/success states for **all four variants in each case**, using image tools. A bounded symmetric sample is1440 entry,390 entry,320 decision/failure/success (five/variant); full-page wide is optional and explicitly not natural post-action visibility. Expand for a named concern. Source and checks can clarify actual behavior. Do not count unviewed filenames as inspected evidence.

Each case needs three separate groups of judgments. For each dimension provide ordered preference groups with ties (for example [["B","D"],["A"],["C"]]), unassessed labels when needed, concrete file/state evidence and tradeoff. If no defensible ordering, put all assessed labels in one tied group. No numeric scores, aggregate wins/novelty/slop score or forced overall repository winner. Judge familiar appropriate patterns positively; font/palette/more effects alone is no quality win. Factual/schematic limitations and exact consequence matter. No detector from any repository is the common judge.

**visualCraft** (four dimensions):

1. Typography, readability and hierarchy.
2. Composition, spacing and rhythm.
3. Media/caption/content craft.
4. Coherence across widths and relevant states.

**productSpecificity** (three dimensions):

1. Supplied facts/artifacts actually shaping the composition.
2. Coherent product direction beyond a replaceable logo/copy shell.
3. Specific decisions preserved across widths/states without task harm.

**taskAccess** (three dimensions):

1. Entry/action priority, decision conditions and truthful consequence.
2. Validation, selection/state retention, failure and recovery.
3. Narrow reading/action access and applicable keyboard/focus/contrast/semantics.

Known technical gate results are scoped evidence. Passing them does not establish comprehension, human usability or accessibility conformance. Inspect normal color renders; no neutralization/uniqueness metric is used. No human/manual test, network, install, commits or Linear. Do not rerun a full automation suite; only a named uncertain blocker permits a bounded read-only check.

Write only assigned reviews/reviewer-N.json and reviewer-N.md. JSON: reviewer, startedAt, finishedAt, inspectedImages (exact packet-relative paths), cases keyed field-fold/relay-notes. Each case has visualCraft/productSpecificity/taskAccess arrays of objects {dimension,groups,unassessed,evidence,tradeoff}. Also findings[{case,label,severity,blocking,evidence}], limitations and resource fields/nulls. Keep evidence concise but comparative and symmetric. Provider/model/tokens/cache/billing/complete resource totals unavailable→null. Resources are reported separately after unblinding, not folded into visual judgments.

Soft10/hard15-minute review budget. Freeze initial judgments and send SHA256s before treatment identity is revealed. Do not overwrite after unblinding; any correction/clarification is separate. Procedural blinding is not immune to inference from style/source conventions; disclose limits, ties and uncertainty.
