# Everyday Teapot: local UI plan
Primary surface purpose: decide. Success is choosing an available glaze and quantity, understanding complete purchase conditions, and seeing an honest cart simulation outcome. Fixed source: fixture.json and shared teapot.svg. No remote sources, dependencies, transaction capability, testimonials or urgency.

Structure A (selected): illustration beside a continuous purchase panel, with identity → physical specs → glaze/availability → quantity → delivery/returns/care → shipping-inclusive review → simulated action/confirmation. Narrow screens place the compact illustration before the same decision sequence. This established single-product pattern and fixed requirements settle the structure; additional runnable alternatives were not created under the single implementation/preview contract.
Structure B (considered, not implemented): full-width photographic-style introduction then an option/review step. Rejected because it separates practical conditions from the choice and makes mobile users traverse a larger introduction. The illustration is evidence, not an unrelated hero.

All terms remain visible rather than hidden in hover or accordions. Native radios (Iron checked, Ash disabled, Sand enabled) and native quantity select support keyboard input. Total is visible before action, updates on change, and confirmation retains chosen values. Stock does not decrement in this demonstration. Illustration always explicitly says Iron shown; swatches are illustrative.
