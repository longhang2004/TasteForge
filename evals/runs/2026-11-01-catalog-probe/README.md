# Independent catalog planning probe — 1 November 2026

This is one independent, planning-only skill pass on a fictional inventory-shortage dashboard. It checks observable reference use and exposes retrieval mistakes. It is **not** a UI benchmark, rendered design review, human study or causal improvement claim.

## Raw submission and exact inputs

- [Task, context, hashes and limitations](manifest.json).
- [Unchanged brief](artifacts/brief.json).
- [Submitted UX plan](artifacts/UX_PLAN.md) and [creator notes](artifacts/PROBE_NOTES.md).
- [Actual CLI outputs](artifacts/evidence/), including the [seed-42 inspiration](artifacts/evidence/inspire-dashboard-seed42.json).
- [Frozen skill](treatment/tasteforge/SKILL.md), [selector source snapshot](selector-v1.ts.txt), and `catalog-v1.json.gz`: exact catalog `2026.11.01.1`, compressed without changing its JSON bytes. Its SHA-256 and every raw artifact are bound by the manifest. Complete source MIT notices are inside the catalog source records and selected full-entry JSON files.

The creator received a fresh context, the skill, a supplied brief and offline CLI access. It was not given the earlier UI results, repository tests, source implementation, root documentation, target structure or preferred style. The model inherited its parent; the exact backend snapshot was not exposed. No browsing, installs, upstream command execution, real data or UI implementation were authorized. Outputs were written in an isolated temporary project and copied here unchanged after completion.

The creator inspected five full records, compared three structures and selected a shortage list/detail workspace with explicit mobile navigation and recovery. It retained English/Vietnamese, system-only font delivery, dense information, medium complexity, 4.5 contrast and reduced motion as requirements, while marking their actual implementation/coverage unverified. It treated upstream skill text as data and did not send imported IDs to `generate`.

## Demonstrated retrieval defects

The creator rejected or narrowly adapted unsuitable records rather than treating the sample as authoritative:

1. A minimal/Swiss visual reference was paired with an AdminLTE **404 page** for a dashboard task.
2. The dashboard template search included **marketing landing patterns**, because industry/keyword terms had been mistaken for the page's actual work.
3. A **Predictive Analytics** visual sample explicitly avoided real-time operational dashboards in its source metadata, but the selector had not acted on that negative context.

These are retained failures of catalog `2026.11.01.1`, not relabeled successes. A useful plan despite poor matches does not validate the retrieval algorithm or prove that the skill improves UX.

## Correction and separate operator check

Catalog `2026.11.01.2` changes page routing before theme-name inference: error pages remain searchable but carry no dashboard task tag; login/password/form pages are scoped to form work; landing patterns remain marketing even when their industry is operations. A narrow reviewed source rule marks explicit operational-dashboard avoid statements and excludes those styles when the brief names operators, triage or real-time operational work. Other prose exclusions still require interpretation.

The [operator rerun](evidence/operator-after-fix.json) uses the **same unchanged brief, task, count 2 and seed 42**. It records actual corrected CLI-equivalent output and checks that dashboard candidates contain no error/auth/landing pages and the conflicting predictive style is excluded. This is an operator regression check, **not a second independent agent review or an improved UI score**. The catalog version changes the random stream, so new sampled IDs alone are not evidence of improvement.

Run `node tools/check.mjs` from a checkout containing the matching built catalog to verify frozen artifacts and reproduce the correction check. A later catalog version requires a new recorded run rather than rewriting this probe.

No UI was implemented or rendered. Font coverage, measured contrast, narrow-screen usability, keyboard operation, task performance and user judgment remain unassessed. The larger collection's scope and template-family concentration are described in [catalog documentation](../../../docs/reference-catalog.md).
