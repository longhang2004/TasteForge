# Create a new interface

1. Read the relevant project files. Identify the task, audience, language, content, technical constraints, and success condition. Ask only for missing decisions that materially change the interface; proceed with reversible assumptions when appropriate.
2. Start with realistic content and task order. Follow [research and structural planning](research-and-plan.md): inspect the user's references, research a few task-relevant examples when tools allow, compare genuinely different information/interaction structures, and record the selected structure in `UX_PLAN.md` or existing project guidance. Use [design principles](../references/design-principles.md) for unresolved decisions. Keep reference provenance and actual inspection scope.
3. After selecting the task structure, initialize the CLI without overwriting files, complete the brief, and suggest compatible visual directions if available. Compare the explanations rather than choosing the most unusual name. The CLI's visual candidates do not replace the structural alternatives. A sparse gallery and a dense financial tool have different needs.
4. Select one coherent visual treatment. Generate Design DNA once a local direction fits the structure; use the recorded seed to reproduce it. If using `inspire`, inspect selected catalog entries and document the manual adaptation instead: external reference IDs are not token-generating direction IDs. External `DESIGN.md` documents can inform an attributed adaptation. Record intentional deviations, such as an existing brand accent or table-specific density rule.
5. Implement the main task with semantic controls, tokenized styles, and an accessible mobile reading order. Include empty, loading, validation, error, success, disabled, and focus states relevant to the task. Preserve content at zoom and with long translations.
6. Run build and project checks, then the supported source audit. Inspect the rendered result if available. Check task reachability, information relationships, consequence visibility, and narrow-screen priority separately from font/color polish. Report the task behavior, evidence, and unresolved visual or interaction questions. Iterate on demonstrated problems.

Without the CLI, document the same design decisions in project guidance and keep the system small. Do not copy a landing-page recipe when the task calls for a form, comparison, or working tool.
