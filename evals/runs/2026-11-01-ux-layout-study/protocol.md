# Preregistered exploratory UX/layout comparison

Frozen before any creator submission. Twelve fresh cases: three tasks × two requested creator models × no skill/current skill. One generation per cell. Original pilots are not reused as controls or rescored.

## Creation controls

Within each task the exact prompt, fixture, starter and supplied assets are identical. Both conditions can use the same current offline CLI/catalog and the same two-viewport preview helper. The sole assigned treatment is following the frozen current skill. No-skill creators must not read any skill; CLI use remains optional in both conditions. This tests the incremental instruction/workflow under equal resource access, not a tool-plus-data intervention.

Fresh contexts; no previous UIs, operator advice, plans, repository docs, tests or worked examples. Plain HTML/CSS/JS, system fonts and local assets, no browsing/install/remote resources. One implementation pass and one self-review cycle, soft twelve-minute target. TasteForge sampling uses seed 42; this is not a generation seed. Actual durations/deviations and CLI/reference use are recorded. Model backend snapshots, inference seed, token use and matched compute are unavailable. Scheduling order is shuffled before generation with seed 20261101; at most three creator agents run concurrently.

## Evidence and gates

Actual Chromium render at 1440×1000 and 390×844; light theme, reduced motion, en-US, Asia/Ho_Chi_Minh, scale 1. All cases receive the same operator task actions and axe scope. Measure initial control geometry and horizontal overflow on original renders. Capture initial/full, decision, error/retry and outcome states as applicable. Capture a 320px narrow view and a keyboard path as supporting evidence; 320px/keyboard traces alone are not conformance checks. Failures stay in the denominator, with traces and screenshots. No creator repair after submission.

The commerce task now explicitly requires the shipping-inclusive total before adding. Transfer includes a real edit-retention/recalculation check. Inventory requires retained list context and an invalid-input/review/failure/retry path. These strengthened contracts differ from the earlier pilot; cross-run pass rates must not be compared.

Task blockers, external-resource dependence and serious observed accessibility problems are gates: a visually preferred output with a blocker is not declared an overall success. Scripted task success is supporting evidence, not measured ease, comprehension or user task time.

## Neutral-first independent review

Two fresh independent AI reviewers see anonymized views in independently shuffled order, no model/condition/source/plan. Stage 1 supplies neutralized initial renders at both widths plus a decision-state render and a recovery/outcome render, with task/fixture and actual browser observations. A common injected stylesheet removes decorative colors, shadows, radii and display font families while preserving authored region/order/control layout and typography scale. Font replacement can change wrapping; these are diagnostic neutralized renders, not geometry-perfect wireframes. All measurements are taken before neutralization. Neutral CSS and packet hashes are retained.

Before seeing authored colors/font families, each reviewer submits five separate scores (1–5) and concrete evidence per view:

1. **Task entry and priority** — first useful action and task content are discoverable without generic filler displacing them.
2. **Decision information** — related object, quantities/units, cost and consequences are grouped and visible at commitment.
3. **Narrow layout and context** — useful reading order, reflow, reachability and return/edit context survive; mere lack of overflow is insufficient.
4. **Progression and recovery** — intent boundaries, feedback, retained input, correction/retry and distinct outcomes are understandable.
5. **Composition purpose** — major regions have a task role; familiar patterns are acceptable, novelty alone earns no credit.

Anchors: 1 blocking/seriously obscured, 2 material weakness, 3 usable with issues, 4 consistently clear with minor issues, 5 particularly strong and task-specific in inspected evidence. Unassessable dimensions are null with explanation. Each view also gets blockers, unnecessary regions, and an evidence-qualified note about conventional/generic composition; no unsupported author/origin guess or single “AI slop score”.

Stage 2 reveals authored visual captures under the same anonymous IDs, after stage-1 files are hashed. Reviewers append an authored-render assessment of whether visual treatment changes practical readability/action clarity, retaining original scores. They do not learn conditions or compare notes until both complete. Disagreements are published rather than silently reconciled.

## Analysis and boundaries

Report individual dimensions and paired revised-minus-no-skill differences for each model/task block, separately by reviewer. Do not collapse dimensions into one taste metric or infer a population effect from six heterogeneous blocks. State improvements, ties, regressions, blockers, reviewer disagreement and resource-use differences. Seeded source choice is deterministic; model generation is not controlled. Condition blindness is best effort because designs may hint at treatment. AI reviewers are not representative users. Neutral render changes can distort wrapping; verify findings against authored states. A workflow/library size and successful tests cannot establish UX quality.

After all raw evidence is frozen, any product/skill changes require a separate follow-up and must not alter this comparison. The report may conclude that improvements are mixed or unproven. No desired winner is specified.
