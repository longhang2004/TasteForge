# TasteForge v0.2.0-beta.1

This beta puts task structure, context and rendered revision before visual variation. It adds attributed reference research, reproducible external inspiration and worked examples for early feedback. The CLI and standalone skill remain useful independently.

## Added

- `catalog`: search/read 642 offline records from 18 pinned MIT-licensed sources, including 172 style documents/rows, 357 contextual guidance records and 113 template/structure observations. Entries retain provenance, hashes and license notices.
- `inspire`: seeded, task-aware external reference exploration with source-size balancing, contextual exclusions, matching structural candidates and ten review gates retained for every sample. Imported references are distinct from the 20 validated token-generating styles.
- Skill workflows for bounded research, runnable structural alternatives, rendered critique/revision, per-surface visitor purpose and targeted refinement. Existing constraints, meaningful repeated information and justified aesthetic exceptions remain valid.
- Optional text/image/layout/motion research, three original effect studies, a runnable inventory composition and an annotated gallery with original-image/trace links and explicit screenshot scope.
- Preserved exploratory comparisons and forward-tests, including a twelve-UI layout study and an Antigravity/Gemini inventory pair. Original submissions, frozen skills, ratings, diagnostics and limitations remain available.

## Versions and compatibility

All three packages and the workspace are `0.2.0-beta.1`. `tasteforge --version` now reports the CLI package version independently of the validated generator engine.

The DNA schema remains `1.0`; validated engine/knowledge remain `0.1.0`. The original 20 styles, 32 font pairs, 20 palettes and example artifacts are retained. Existing valid v0.1 DNA does not need migration. External reference catalog version is `2026.11.01.2`, with its own recorded seed/version contract.

The runtime minimum remains Node 20.19+. Use a maintained LTS runtime for normal use; preparation checks cover Node 20/22/24/26. The repository CI matrix includes those majors. Native Windows CLI installation and broad agent-host integration are not certified by Ubuntu/WSL validation.

## Verification

`VALIDATION.json` records the actual candidate commit's check environment, runtime matrix, production advisory result, installed-package smoke workflow, unchanged example regeneration, skill packaging and preserved-evidence checks. The source ZIP and manifest identify the commit being prepared; configured remote CI is reported separately from executed local checks.

The saved examples also retain their own executed browser evidence: 77 inventory task/geometry checks, 95 effect-study checks and 108 gallery-viewer checks. These are separate checks of different artifacts, not an aggregate UX-quality score or proof of general improvement.

## Limits and feedback focus

- Reference metadata/task routing are reviewed heuristics. Catalog size, seeded variation and source popularity do not establish task suitability or human authorship.
- `inspire` produces references, not validated DNA. Effects and per-surface editing intentions are skill guidance, not extra CLI commands or a new browser detector.
- Audits inspect supported source syntax; they do not resolve the complete runtime cascade, guarantee accessibility or certify visual quality. Font delivery and actual language rendering remain implementation work.
- Exploratory evidence shows local gains and regressions. AI reviews and scripted success do not establish representative-user comprehension, ease or reliable removal of generic composition. Human/user validation remains pending.
- OpenCode attempts for the requested free DeepSeek/GLM models were quota-blocked; no UI outputs or quality conclusion are attributed to those attempts.

Useful beta feedback: an actual brief and target task, chosen sources, wide/narrow review/error captures, preserved-context failures, false-positive audit findings and concrete agent-host installation problems. Avoid sending credentials or customer data in public reports.
