# Checking design evidence discovery

The live checks below used public, synthetic briefs on 27 November 2026. They exercise the search path in the shipped skill. They supply no new human ratings of the proposed interfaces.

Across the four successful queries the services returned eighteen candidate links. We cite the specific material inspected, including primary documents found by refining the search. A separate Crossref query about website complexity returned HTTP 429 during the same session. The helper surfaced the error. Open-web search retrieved the original first-impression study. Repeating the same public query on another date can change the results.

## Repeat the checks

Run `python3 scripts/find-design-evidence.py --help` from the skill directory, then run a command from the table with the same script. With no web tool, report the unavailable evidence and use the attributed local catalog if relevant. With web access, read a candidate and look for an example that would change the proposed design before recording a decision. [The research record](2026-11-27-design-preferences.md) contains the full briefs and the competing evidence.

For deterministic checks from the repository root:

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
pnpm pack:smoke
```

The offline tests exercise query encoding, result bounds, canonical links for each provider, empty results, malformed responses, timeouts and rate limiting. Package smoke checks require the guide and helper to be present in the CLI archive. The CI matrix performs these checks without querying the live indexes.
