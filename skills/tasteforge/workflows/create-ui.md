# Create a new interface

1. Read the relevant project files. Identify the task, audience, language, content, technical constraints, and success condition. Ask only for missing decisions that materially change the interface; proceed with reversible assumptions when appropriate.
2. Start with realistic content and task order. Sketch the information hierarchy before choosing decorative treatment. Read [design principles](../references/design-principles.md) and the topic references needed for unresolved decisions.
3. If the CLI is present, initialize without overwriting files, complete the brief, and suggest compatible directions. Compare the explanations rather than choosing the most unusual name. A sparse gallery and a dense financial tool have different needs.
4. Select one coherent direction. Generate Design DNA once the choice is supported; use the recorded seed to reproduce it. Record any intentional deviations, such as an existing brand accent or a table-specific density rule.
5. Implement the main task with semantic controls, tokenized styles, and an accessible mobile reading order. Include empty, loading, validation, error, success, disabled, and focus states relevant to the task. Preserve content at zoom and with long translations.
6. Run build and project checks, then the supported source audit. Inspect the rendered result if available. Report the task behavior, evidence, and unresolved visual or interaction questions. Iterate on demonstrated problems.

Without the CLI, document the same design decisions in project guidance and keep the system small. Do not copy a landing-page recipe when the task calls for a form, comparison, or working tool.
