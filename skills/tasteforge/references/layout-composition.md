# Layout and composition

Start with information relationships and reading order. Use a grid to align those relationships, not to force unrelated content into identical cards. Shared edges help scanning. Asymmetry can create emphasis when supporting content still has a clear place.

Use a small spacing scale. Keep within-group gaps smaller than between-group gaps. Allow optical or content-driven exceptions and record recurring ones as tokens. A particular margin value is not inherently correct; its relationship to nearby content matters.

Poor: a desktop three-column checkout squeezed onto a phone. Improved: stack order summary and fields in task order, retain essential price information, and keep the action reachable without obscuring content. Poor: flatten a comparison table into unrelated tiles. Improved: maintain comparable columns with purposeful horizontal scrolling, row labels, and a clear affordance when necessary.

Choose breakpoints where content stops working rather than by device names alone. Test long headings, empty lists, large datasets, localization, narrow widths, and zoom. Avoid fixed heights around variable text. Use intrinsic layouts and bounded reading widths. When visual order differs from DOM order, recheck keyboard and screen-reader sequences.

Density is contextual. Expert tools often need compact tables and persistent controls; new users may need explanation and progressive disclosure. Spacing should clarify work, not merely enlarge the page.
