# Copy that explains the task; states that stay coherent

Read this for an unresolved copy or secondary-state concern. For a settled Fast correction, use only the relevant check and existing product context. No new research, plan, prototype or redesign is required.

## Check information value

Ask what this visitor learns about the **action, object, condition, consequence or evidence**. Truthful brand expression can still leave the next step unclear. Keep approved voice, legal wording and required facts; do not invent metrics, customers, capabilities or persistence to make copy sound specific.

Try replacing the product name with an unrelated one. If the sentence still fits, investigate what information is missing. This is a question, not a slogan-syntax or punctuation ban. A campaign line with concrete explanatory copy can be useful; an operational form usually needs the actual action and conditions.

Original fictional examples, conditional on the implementation:

| Context            | Useful distinction                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| Local file import  | Name the supported action/type; show only verified limits, not an invented upload cap.                        |
| Invalid field      | Explain the actual failed rule and correction; retain valid entries and appropriate error association.        |
| No filter matches  | Name the active-filter scope and available reset; do not imply the collection has no records.                 |
| Local draft result | State what actually changed and its persistence scope; do not imply an account save or completed transaction. |

## Carry meaning across relevant states

Select states that exist or are required: entry, loading/pending, first-use or filtered-empty, invalid input, failure/retry, success, edit/return. Do not invent backend states to fill a checklist.

For each, retain the product nouns, hierarchy, content relationship and action meaning. Geometry can change appropriately. An empty collection can simplify its layout; it still needs a truthful explanation and the available next step. A retry should preserve choices within the actual persistence contract.

Use proportionate visible and programmatic feedback. Applicable status messages need appropriate exposure without requiring focus movement; this does not mean a toast or live region for every action. A screenshot does not prove announcement or keyboard behavior.

## Refine without losing the contract

Before a consequential edit, note the items at risk: required facts/units, labels, links/routes, fields/actions, relevant handlers/selectors/test hooks, entered values, filters and recovery. A small fix can use a few lines in existing notes.

Map those items to the result. Remove something only for an authorized task reason, never just to clear a warning. Keep meaningful repetition, conventional controls/cards/tables and justified brand fonts. Editorial paper/serif treatment needs a content reason too; replacing one fashionable default with another is not a quality goal.

At the actual minimum supported width, inspect required text and reachable actions. Preserve Vietnamese diacritics, real long labels, units and fixed font/delivery constraints. Adjust wrapping/hierarchy or approved wording; clipping required content is not evidence of responsive success. Apply reflow requirements and their two-dimensional exceptions to the actual surface.

## Check, decide, stop

Record **target/state/width → evidence → consequence → keep/adapt/remove/unassessed → recheck**. Inspect normal rendered information priority before mechanical warnings when practical. Source facts, rendered observations, executed behavior, AI judgments and human findings remain distinct.

Make one bounded correction and recheck the affected state/behavior and shared width rules. Reuse relevant existing evidence when it still applies. No fresh A/B exercise or recruited panel is required for a scoped correction; a claim about users or future generations needs its own suitable evidence. If no meaningful issue is found, keep the design and report scope/unknowns.
